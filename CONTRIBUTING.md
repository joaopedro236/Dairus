
# Contributing to Dairus

## About

Dairus is an independently developed social platform focused on providing a modern, intuitive, and accessible social experience.

This document outlines the development standards and contribution guidelines followed throughout the development and maintenance of the project.

## Development Guidelines

- Keep the code clean, organized, and readable.
- Follow the existing project architecture.
- Respect the separation of responsibilities.
- Avoid unnecessary code duplication.
- Prioritize security, accessibility, and performance.
- Document relevant changes.
- Test features before submitting changes.
- Maintain consistency with existing naming conventions.

## Commit Convention

Commits should follow the Conventional Commits specification.

Examples:

- `feat: add new feature`
- `fix: correct unexpected behavior`
- `refactor: improve code organization`
- `docs: update documentation`
- `perf: optimize performance`
- `chore: update dependencies`
- `test: add automated tests`

## Branch Naming

Branches should follow a descriptive naming convention.

Examples:

- `feat/new-feature`
- `fix/bug-fix`
- `refactor/code-improvement`
- `docs/documentation-update`
- `test/automated-tests`

## Security

- Never commit credentials, API keys, or access tokens.
- Keep sensitive environment variables outside the source code.
- Validate user inputs and permissions.
- Follow secure authentication practices.
- Report security vulnerabilities responsibly.
- Regularly review project dependencies.

## Maintenance

Dairus is currently maintained and developed independently by its creator.

Suggestions, bug reports, and improvements can be submitted through GitHub Issues.

## Development Philosophy

Dairus values clean code, maintainability, modular architecture, and continuous improvement.

Contributions should respect these principles.
